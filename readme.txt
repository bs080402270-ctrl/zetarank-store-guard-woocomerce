== Description ==

ZetaRank StoreGuard for WooCommerce adds lightweight security controls to customer-facing WooCommerce forms.

Features include:

* CAPTCHA protection with local math CAPTCHA or Google reCAPTCHA v2 on classic forms.
* Native WooCommerce Checkout Block / Store API security challenge with server-side validation.
* Brute-force login protection using temporary per-IP and per-username limits.
* Registration protection with CAPTCHA, honeypot checks, minimum form-fill time, and rate limiting.
* Classic WooCommerce checkout protection with CAPTCHA, honeypot checks, minimum form-fill time, and rate limiting.
* Checkout Block protection with a native math challenge, minimum completion time, and rate limiting.
* Lost-password form protection.
* Optional Contact Form 7 integration.
* Configurable attempt limits and lockout duration.
* No PHP sessions required by the classic-form CAPTCHA system.
* WooCommerce HPOS compatibility declaration.
* WooCommerce Cart and Checkout Blocks compatibility declaration.

Checkout Block protection uses WooCommerce's Additional Checkout Fields API and validates the answer server-side through the Store API. This means direct Store API checkout submissions must also satisfy the security challenge. Checkout Block security requires a WooCommerce version that provides the stable Additional Checkout Fields API (WooCommerce 8.9 or newer). On older WooCommerce versions, classic checkout protection continues to work.

For Checkout Block / Store API, StoreGuard uses its built-in math security challenge even when Google reCAPTCHA is selected for classic forms. This avoids depending on a browser-only widget for Store API validation.

== External Services ==

= Google reCAPTCHA v2 =

StoreGuard optionally integrates with Google reCAPTCHA v2 to help distinguish human visitors from automated bots on supported classic forms. Google reCAPTCHA is not required: the plugin defaults to its local math CAPTCHA, and no reCAPTCHA requests are made unless a site administrator selects Google reCAPTCHA and configures the required keys.

When Google reCAPTCHA is enabled, the plugin loads Google's reCAPTCHA JavaScript from `https://www.google.com/recaptcha/api.js` in visitors' browsers on pages where StoreGuard may display a protected form. As a result, the visitor's browser connects directly to Google and Google may receive information associated with that request, such as the visitor's IP address, browser/device information, cookies, and other data described in Google's policies.

When a visitor submits a protected form, StoreGuard sends the reCAPTCHA response token generated by Google, together with the configured secret key, to `https://www.google.com/recaptcha/api/siteverify` so Google can verify whether the challenge was completed successfully. This verification request is made only when Google reCAPTCHA is configured as the CAPTCHA provider and a protected form is submitted.

Google reCAPTCHA Terms of Service: https://cloud.google.com/terms/
Google Privacy Policy: https://policies.google.com/privacy
Google reCAPTCHA information: https://www.google.com/recaptcha/about/

StoreGuard's built-in math CAPTCHA, honeypot, timing checks, brute-force limits, and rate limiting operate locally on the WordPress site and do not require an external service.

== Installation ==

1. Upload the plugin ZIP through Plugins > Add New > Upload Plugin, or copy the `zetarank-storeguard` folder to `/wp-content/plugins/`.
2. Activate ZetaRank StoreGuard for WooCommerce.
3. Go to WooCommerce > StoreGuard Security.
4. Choose the protected forms, CAPTCHA provider, and rate limits.
5. Keep WooCommerce Checkout Block / Store API enabled to protect block-based checkout.
6. If using Google reCAPTCHA v2 for classic forms, enter your site key and secret key.

== Frequently Asked Questions ==

= Does the plugin require Google reCAPTCHA? =

No. The default math CAPTCHA works locally without an API key.

= Does it support the WooCommerce Checkout Block? =

Yes. Version 2.1.0 adds native Checkout Block / Store API protection using WooCommerce's Additional Checkout Fields API. The challenge is validated on the server, so it also applies to direct Store API checkout requests.

= Why does Checkout Block use math CAPTCHA when reCAPTCHA is selected? =

The Checkout Block sends checkout data through the Store API. StoreGuard uses a native field and server-side math validation there so the security check is enforced by the API itself rather than depending only on a browser widget.

= What does brute-force protection do? =

Repeated failed login attempts are counted by IP address and username. Once the configured threshold is reached, further interactive login attempts are temporarily blocked.

= How are bots blocked? =

Classic protected forms include a hidden honeypot plus a signed form-time token. Checkout Block uses a server-side challenge, timing validation, and rate limiting through the Store API.

= Does it protect registration? =

Yes. Registration can use CAPTCHA, bot checks, and a separate temporary rate limit.

= Does it protect checkout? =

Yes. Both classic WooCommerce checkout and the WooCommerce Checkout Block are supported. Checkout Block support requires WooCommerce 8.9 or newer.
